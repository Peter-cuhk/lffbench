# L6-A `l6_swap_interrupt`：交换两件物品，第二次搬运时打滑

| 项 | 内容 |
|---|---|
| 等级 | L6 修正进度判断（时序 / 记忆）：忘了做到哪一步，重复或跳过子步骤 |
| 能力 | Perceive（看出打滑；在外观相同的垫子之间按位置对应）、Save（记住开局布局和已完成的步骤）、Retrieve（打滑后取回）、Utilize（从正确的那一步继续） |
| 协议 | within：一个 episode 不重置，k = 5 次"尝试"（粒度见 §1） |
| 代码 | `lffbench/tasks/l6_swap.py`，`SwapInterrupt`；验证 `python scripts/validate.py --task l6_swap_interrupt --n 20 --k 5` |
| 场景 | 4 块外观完全相同的深灰圆垫（直径 11 cm，扁平标记，不参与碰撞）。奶油奶酪 X 在垫 A，黄油 Y 在垫 B，垫 C、D 空。4 块垫的位置每个 seed 随机（中心间距 ≥ 17 cm，离机器人基座水平距离 ≤ 0.71 m），哪块是 A/B 也随之随机；两件物品朝向 ±0.3 rad 随机 |
| 指令（直呼其名） | "Swap the positions of the cream cheese and the butter: each must end up on the round pad where the other one started. You may use the empty pads as temporary spots." |
| 指令（间接描述） | "Swap the positions of the pale blue box with the oval logo and the red-and-yellow box: …"（奶油奶酪是浅蓝/银色盒、蓝色椭圆标；黄油是红黄色盒） |
| 成功 | X 中心离 B 中心 ≤ 4 cm、Y 中心离 A 中心 ≤ 4 cm，两件都静止在桌面上、不在夹爪里 |
| 失败注入 | 交换的第二次搬运途中（例如标准流程 X: A→C、Y: B→A、X: C→B 里的 Y: B→A），被搬的物品"打滑"：夹爪张开，物品出现在桌面上一个隐藏的落点（不在任何垫子上，朝向随机） |
| 隐变量 | 落点：靠近哪块"诱饵垫"（spare 备用垫 50%、source 被搬物品自己的起点垫 25%、dest 它真正的目的垫 25%），方位角，离诱饵垫中心 11.5–14 cm（保证诱饵垫比其他垫至少近 3 cm、物品完全不压垫），落地朝向；触发距离（物品离开起点 5–10 cm 时触发）。开局布局本身不是隐变量——第一帧里看得见，打滑之后才从画面上消失 |
| 先验为什么失败 | 打滑后画面是：X 在 C、Y 躺在桌上、A/B/D 三块空垫一模一样。只看当前画面的 agent 不知道 X 已经停在临时垫上、也不知道 A、B 是哪两块，只能猜；"放到最近的空垫"在 75% 的实例里是错的 |
| 要从失败里带走 | 已经做了什么（X 已停在临时垫 C）、还剩什么（Y→A，然后 X→B），以及 A、B 在哪——这些只在 agent 自己的历史里 |

## 1. 一次"尝试"的粒度（within 协议）
- 尝试 = agent 从当前状态开始操作、直到它宣布"做完了"为止（脚本策略里是把机械臂收回初始位姿，让出视野）。然后测 outcome、给 F0/F1/F2 反馈；没成功就从当前状态（不重置）开始下一次尝试，最多 5 次。succ@j = 第 j 次尝试结束时已经成功的 run 占比。
- 打滑每个 episode 只注入一次，发生在第 1 次尝试内部。触发看状态、不看脚本（在 Skills 的每个控制步回调里检查）：某件物品被夹着举高 ≥ 5 cm、离开自己起点 ≥ 触发距离，并且另一件已经离开了自己的起点垫——即"交换的第二次搬运"，不管 agent 先搬哪件、用哪块垫当临时位。所以接 VLM agent 时不用改任务代码。
- 打滑是尝试内部的失败事件：当场由 `task.drain_events()` 返回 "The butter slipped out of the gripper and fell onto the table."，harness 应把它附在当时那次工具调用的执行报告里；agent 可以在同一次尝试里恢复。因此 oracle / adaptive 的 @1 包含"掉落后在同一次尝试内恢复"。
- `run_scripted` 返回的 history 和 cross 协议同格式：`[{attempt, params, outcome}]`。`params` 记这次尝试的计划和每一步搬运（物品、从哪块垫、到哪块垫、是否夹住、是否打滑），`outcome` 记成功与否、每件物品的位置 / 所在垫 / 离目标距离、打滑事件和 F2 文本。

## 2. 反馈（F2 只给当前可观测状态 + 本次尝试里的事件）
- F0：只有图像。F1：再加 "Attempt failed." / "Attempt succeeded."
- 打滑当时（事件）："The butter slipped out of the gripper and fell onto the table."——不说它原来在哪块垫、要去哪块垫。
- 尝试结束（F2，validate 实测原文，seed 1001 naive）："Attempt failed. During this attempt: The butter slipped out of the gripper and fell onto the table. Now the cream cheese is on the pad at (0.58, -0.24); the butter is on the pad at (0.67, -0.06); empty pads at (0.46, +0.18), (0.42, -0.15) (robot base frame, m)."
- 同一 seed、blind 第 2 次尝试后："Attempt failed. Now the cream cheese is on the pad at (0.42, -0.15); the butter is on the pad at (0.67, -0.06); empty pads at (0.58, -0.24), (0.46, +0.18) (robot base frame, m)."
- 刻意不给的东西：哪件放错了、它该去哪块垫。如果 F2 说"黄油不在奶油奶酪原来的垫子上"，就是裁判替 agent 记住了开局布局，题目就不考记忆了；而且 4 块垫时逐次排除也能凑出答案。

## 3. 脚本参照策略（"感知"用仿真状态）
所有策略第 1 次尝试都先按第一帧做同一个开环计划：临时垫 = 离 A 最近的空垫，X→临时垫、Y→A、X→B。打滑后各自恢复：

| 策略 | 有什么记忆 | 打滑后 / 之后的尝试怎么做 |
|---|---|---|
| oracle | 真实开局布局（特权） | Y→A、X→B |
| adaptive | 第一帧存下"哪件在哪块垫（按位置）"和步骤日志 | 取回记忆：Y→X 的起点垫、X→Y 的起点垫；后续尝试若有物品偏离目标，按记忆 + F2 再摆正 |
| naive | 无（只看当前画面；1 次尝试） | "继续完成、凭画面猜"：桌上那件放到离它最近的空垫，还在垫上的那件放到离它最近的剩余空垫 |
| blind | 无（每次尝试只看当前画面） | "不记得做到哪步、从头再来"：先把桌上那件放到最近的空垫，再把两件按当前位置完整交换一遍；之后每次尝试都再交换一遍（重复交换，RMBench 观察到的失败） |
| blind_continue（附加对照，不在验收表里） | 无 | 第 1 次 = naive，之后每次都再交换一遍 |

## 4. headroom 验证（实测，2026-10-06，n = 20，seed 1000–1019，k = 5，`results/l6_swap_interrupt/validate.json`）
| 策略 | @1 | @2 | @3 | @5 | 验收线 |
|---|---|---|---|---|---|
| oracle | 100% | | | 100% | @1 ≥ 90% ✓ |
| naive | 20% | | | 20% | @1 ≤ 25% ✓ |
| adaptive | 100% | 100% | 100% | 100% | @5 ≥ 80% ✓ |
| blind | 0% | 0% | 0% | 0% | @5 ≤ 40%、明显低于 adaptive ✓ |

同一次运行的其他实测：
- 80 个 run 全部触发了打滑，落点和采样时预算的落点一致（差 < 2 mm）。
- 600 次搬运 0 次没夹住；成功 run 的物品离目标垫中心平均 0.32 cm、最大 1.14 cm（阈值 4 cm）。所以 oracle / adaptive 的 100% 不是靠运气，失败全部来自"放错垫子"，不是执行误差。
- 20 个实例的诱饵分布：spare 9、source 6、dest 5。naive 的 4 次成功正好是 dest 诱饵里 X 恰好被放到 B 的 4 个；dest 诱饵里还有 1 个（seed 1005）X 被放到备用垫而失败。
- naive 的 16 次失败里 6 次（全是 source 诱饵）结束状态 = 开局布局（Y 回到 B、X 回到 A），画面看起来"什么都没发生"。
- 每个 seed 四种策略合计约 40 s（8 核机器，负载 30+，单线程）；整次验证 791 s。

## 6. 只看当前画面的策略最多能拿多少（几何推算，不是仿真实测）
假设执行完美，只算"打滑后把两件放到哪两块垫"，1500 个实例（seed 5000–6499），当前诱饵分布：

| 无记忆策略 | @1 | 再交换一次后（@2） |
|---|---|---|
| 最近空垫（= naive） | 12% | 31% |
| 均匀随机（6 种放法） | 17% | 33% |
| 反着来（Y 不放最近的那块，其余随机） | 19% | 38% |
| "落点旁边就是黄油起点"（X→离落点最近的垫，Y 随机） | 13% | 24% |
| 先复原再说（X→离临时垫最近的垫，Y→剩下离落点最近的） | 7% | 30% |

- 第二列只多一次"再交换一次"：如果第一次猜成了开局布局（X 回 A、Y 回 B），再交换一次就成功。这是 4 块垫的结构性下限：随机猜 + 再交换 = 1/6 + 1/6 = 1/3。
- 再往后随机换别的放法（每次 1/11）到 k = 5 约 43%（解析估计，假设无记忆 agent 每次在 11 种其他放法里均匀挑）。所以有记忆（100%）与最好的无记忆随机搜索（约 40%）之间的差距约 60 个百分点，但 blind 的 0% 是"重复交换"这一种无记忆行为的值，不是所有无记忆 agent 的上限。
- 3 块垫（用户草案）时：打滑后只有 A、B 两块空垫，随机猜 50%，猜错的结果恰好就是开局布局，再交换一次必成——无记忆的"猜 + 重做"到 @2 就是 100%。这是改成 4 块垫的原因（§7-1）。
- 诱饵分布的影响（同一推算）：如果按草案让落点主要靠近 B（source 50%、spare 30%、dest 20%），"最近空垫 + 再交换一次"到 @2 是 46%（"先复原再重做"的捷径）；均匀 1/3 时 43%；现在的 25/50/25 时所有简单无记忆策略在 @2 都 ≤ 38%，接近 1/3 的下限。

## 7. 设计决定和理由
1. **4 块垫，不是草案的 3 块。** 3 块垫时无记忆"猜一下、错了就再交换"到第 2 次尝试必成（§6），blind 不可能低于 adaptive。多一块完全相同的备用垫，把无记忆的随机下限从 1/2（@2 时 1）降到 1/6（@2 时 1/3）。5 块垫能再降到约 1/12（@2 时 1/6），但在 ≤ 0.71 m 的可达范围里放不下 5 块垫再加不压垫的落点，要换更大的工作区。
2. **落点"靠近诱饵垫"，诱饵 spare 50% / source 25% / dest 25%。** 草案建议偏向 B（source）。实测/推算发现 source 偏重时，"把两件都放回最近的垫"会恰好复原开局布局（临时垫一般就选在 A 旁边，所以离 X 最近的是 A），再做一次交换就成功——等于给无记忆 agent 开了后门（§6）。现在的分布让"最近的垫"在 75% 的实例里是错的，同时不让任何一种简单的反向推理占便宜。
3. **naive 和 blind 分别代表 L6 的两种失败。** naive = "跳步 / 猜错位置"：知道自己在交换中途，但不知道哪块垫是谁的；blind = "重复步骤"：不知道做到哪一步，从头再交换（用户举的 RMBench 例子）。blind 的第 1 次尝试因此和 naive 不同（cross 协议里 blind@1 = naive@1，这里不是）。blind 的 0% 是结构性的：重新交换后 Y 落在临时垫 C 上，C 永远不是目标，之后每次交换只是在两种错误状态之间来回。
4. **adaptive 第 1 次就成功。** L6 的"失败"是打滑这一事件，修复所需信息在 agent 自己的历史里；把历史存好、取回、用对的 agent 本来就等价于 oracle。之后的尝试只用于修正执行偏差（本次验证里没用上）。
5. **F2 不泄露开局布局**（§2）。
6. **打滑用传送实现**：夹爪张开 + 物品直接出现在落点（朝向随机，平放在桌面上，用 `envs.place_upright`）。这样落点可控（不压垫、离诱饵近、在可达范围内）。代价是视频里物品"瞬移"，不是真实的掉落轨迹。
7. **垫子是不碰撞的扁平圆片 + 重力补偿**（MJCF 里 `gravcomp="1"`，必须写进 XML；运行时改 `body_gravcomp` 不生效，因为 `ngravcomp` 是编译期算的）。不加的话无碰撞物体会穿过桌面掉下去。4 块垫各注册一个类名（LffSwapPadA–D，XML 相同）：LIBERO 的 BDDL 解析器按类别存物体，同一类别写多行只保留最后一行。
8. **工作区收紧到离基座 ≤ 0.71 m（垫子）/ ≤ 0.73 m（落点）**：实测在 x = 0.10、y = 0.19（离基座 0.78 m）放完物品后，手臂完全伸直（关节 4 到限位），OSC 卡死，下一次抓取失败。收紧后 29 个点（含四角）的往返测试全部到位，validate 里 0 次抓取失败。

## 8. 如果 agent 把完整历史都放在上下文里，这题会不会太简单？
- 会简单很多（推测，未用 VLM 测）。所需信息就在第一帧：开局时奶油奶酪和黄油各在哪块垫。上下文里留着第一帧的 agent 只需要 (a) 看出打滑，(b) 回看第一帧，(c) 把第一帧里的垫子和现在的垫子按位置对上（垫子一模一样，只能靠位置/相对关系），(d) 意识到 X 现在在临时垫上，还要再搬一次。对强 VLM，(a)(b)(d) 大概率不难；(c) 在 256–512 px 的 agentview 里有一定难度（物品约 25 px、垫子远近透视不同），但应该也不难。
- 所以这题在"全历史"设定下主要测 Retrieve + Utilize + 跨帧空间对应，测不到 Save。要让它真正考记忆，建议在 harness 层做，不用改任务：
  1. **有限历史**：只保留最近 N 帧图像（例如 N = 2）+ agent 自己写的文字笔记。此时 agent 必须在开局主动写下"cream cheese on the pad at (x, y), butter on the pad at (x, y)"（Save），打滑后再读出来。可以报告"有笔记 / 无笔记"两个条件。
  2. **拉长流程**：在开局和打滑之间插入更多步骤，让第一帧被挤出上下文窗口——例如两对物品依次交换（6 块垫、打滑发生在第二对的第二次搬运），或三件物品轮换（A→B→C→A）。这需要新写一个变体（未实现）。
  3. **更多一模一样的垫子**：降低无记忆的随机下限（§6、§7-1），需要更大的工作区。
  4. **只给 F0/F1**：去掉 F2 里垫子的坐标，agent 必须自己从图像里定位垫子。
- 反过来也要报告：只看当前画面（每步只给当前帧）的 agent 应该落在 §6 的范围（@1 约 12–19%，@2 约 1/3）；如果某个 VLM 在"只给当前帧"条件下明显高于这个范围，说明画面里还有我们没想到的线索，需要复查。

## 9. 已知问题 / 效度威胁
实测到的：
- 附加对照 blind_continue（naive 之后每次再交换一次）在这 20 个实例上 BC_PLACEHOLDER。原因是这 20 个里 source 诱饵占 6 个（期望 5 个），而 source 诱饵时 naive 的结束状态全部恰好是开局布局（§4），再交换一次就成功。几何推算的期望是 @2 约 31%（§6）。也就是说：blind 的 0% 依赖"重复整套交换"这一种无记忆行为；"先按最近的垫收拾、错了再交换"的无记忆 agent 在这组种子上能到约一半。报 ΔICL 时应该用真正的"只给当前帧"条件跑 VLM，而不是只引用 blind 的 0%。
- 物品在 384 px agentview 里只有二十来个像素，远处（靠近机器人）的垫子透视压缩明显；垫子靠近机器人一侧时，搬运中会被机械臂挡住（见 `slip_*.png`）。真正跑 VLM 时建议 512 px，并给腕部相机。
- 打滑是传送，不是物理掉落；视频里物品会从夹爪里"消失"、在落点"出现"，没有下落过程。
- 奶油奶酪和黄油的 HOPE 碰撞体是平放的扁盒（8 × 4.3 × 1.8 cm），从 agentview 斜着看，奶油奶酪的视觉网格看起来比较"高"；抓取和成功判定都按碰撞体，验证里没有出问题。

推测、未验证的：
- 强 VLM 在"全历史"条件下大概率接近 adaptive（§8）；在"只给当前帧"条件下应接近 §6 的无记忆范围。都没用真模型测过。
- "最近空垫"是不是 VLM 的真实先验不确定；VLM 也可能直接宣布完成（X 留在临时垫上，必败），或者只把黄油放回某块垫就停。
- 打滑触发规则对非标准做法（例如 agent 先把两件都挪到空垫上再分别放回）也会在"第二次搬运"触发，落点按当时的布局重新计算；这类情况的落点分布没有专门验证，代码里有退回到其他诱饵 / 预算落点的兜底。
