# L1-A `l1_bias_place`：机械臂有标定偏差时，把奶油奶酪放进碗里

| 能力 | Perceive（从失败画面/测量里看出夹爪偏在哪个方向、偏多少）、Utilize（把估计出的偏差带到下一次，抓和放的每个指令位置都要减掉） |

| 指令（间接） | "Pick up the flat blue box with the white oval label and put it into the round grey bowl." |
| 场景 | LIBERO `cream_cheese`（平放，8.12 × 4.27 × 1.79 cm，蓝色盒子、白色椭圆标签）+ `akita_black_bowl`（口内径约 9.2 cm、高 5 cm，斜壁）+ 干扰物 `butter`、`chocolate_pudding`、`orange_juice`（13 cm 高纸盒）。全部位置按 seed 随机：奶酪 x ∈ [−0.16, 0.04]、y ∈ [−0.20, 0.20]，yaw ±10°；碗距奶酪 ≥ 20 cm；干扰物彼此 ≥ 11 cm、离奶酪/碗 ≥ 13 cm；橙汁盒离奶酪和碗 ≥ 17 cm，不挡正面相机，不在搬运直线上 |

| 隐变量 | 固定标定偏差 b = r(cos θ, sin θ, 0)，r ~ U[2.5, 4.0] cm，θ ~ U[0, 2π)，加在所有指令位置上（`Skills(bias=b)` / `skill_bias(inst)`）。agent 看不到 b；回报给 agent 的末端位置在指令系（真值 − b），见"已知问题" |
| 质量 | 改成真实量级：奶酪 227 g、黄油 250 g、布丁 200 g、碗 300 g（LIBERO 默认 5–10 g） |
| 成功判据 | 奶酪中心到碗中心水平距离 < 4.6 cm、奶酪中心低于碗沿、碗直立且在桌上、奶酪不在夹爪里 |

## 为什么先验会失败
先验 = 完美感知（用奶酪、碗的真实位置）+ 标准动作（夹爪对准奶酪中心、跨短边从上往下抓 → 提起 → 移到碗上方、手指高过碗沿 → 松开），但不知道 b。

- 夹爪实际落在"指令位置 + b"。b 在**横跨奶酪方向（夹爪闭合方向）**的分量 b⊥ 一旦超过约 0.7 cm，一根手指就落在奶酪顶面上，手被托高约 1.5 cm，夹爪在奶酪上方合拢，抓空。腕部相机里能清楚看到一根手指压在奶酪上，另一根悬在旁边（`results/l1_bias_place/keyframes/*_naive_close.png`）。
- b 沿奶酪长边的分量 b∥ 基本不影响：手指垫可以夹在 8.1 cm 长边上的任何位置；而且抓和放加的是同一个 b，手里的偏置在放的时候正好抵消；碗是斜壁的，很宽容。所以第一次成不成，几乎只取决于 b⊥。b∥ 大时手指夹在奶酪一端附近，偶尔在搬运中滑落：开发运行 seed 2004（b∥ = +3.2 cm、b⊥ = +0.9 cm）出现过一次 "dropped"；人为设 b⊥ = 0.2 cm、b∥ = 3.5 / 3.8 cm 时两次都成功。

## 要从失败里学到什么
F2 报告"夹爪合拢的位置相对奶酪中心偏前/后、偏左/右各多少 cm"。这个偏移就是 b 本身（实测误差见下），所以**一次失败后就能估计出 b**，下一次把抓和放的所有指令位置都减去它。学到的是"同一种方法，指令位置整体平移多少"，方法本身不用变。

## 参照策略
| 策略 | 做法 |
|---|---|
| oracle | 所有指令位置减去真实 b |
| naive | 指令位置 = 真实物体位置（偏移 0） |
| adaptive | 维护偏差估计：每次失败后把 F2 的 `grasp_offset` 累加进去（夹爪没合拢过时用 `release_offset`），下一次所有指令位置减去估计值 |
| blind | 不看历史；每次重试给目标加 N(0, 5 mm) 的随机偏移 |

脚本策略：yaw 对齐奶酪长边，先到抓取点上方 8 cm，再降到 z = 桌面 + 1.05 cm（手指凸包最低点在夹爪点下 0.97 cm，刚好不蹭桌面），合拢，以 0.3 m/s 升到桌面 + 20 cm；没夹住就停（真实控制器能看到夹爪空合），夹住了就移到碗上方、降到夹爪点高过碗沿 1.2 cm 处松开。

## 设计决定与理由
1. **容器：`akita_black_bowl`，不用 ramekin。** LIBERO 的 `glazed_rim_porcelain_ramekin` 内径约 7.1 cm（由碰撞盒算），奶酪长 8.1 cm，平放放不进。试过把 ramekin 网格 xy 放大 1.35–1.40 倍、做成"刚好能放下"的紧配合容器，让放置成为精度瓶颈。实测两个问题：(a) 偏了以后奶酪不是掉到外面，而是斜着卡在碗里，一角高出碗沿 1–2.5 cm；横向偏差为 0、只沿长边偏 0.6 cm 时也出现过斜立（seed 1001）。看起来"在碗里"，成功判据定不干净。(b) 手指在碗里张开（8 cm）会撑住内壁，抬手时把碗一起提起来。所以放弃，改用斜壁宽容的 akita 碗，精度瓶颈放到抓取上。
2. **精度瓶颈放在抓取，用短行程夹爪。** 用原生 8 cm 行程，4.27 cm 宽的奶酪抓取容差约 ±2.2 cm（实测，见上）。r ∈ [2, 3.5] cm 时按均匀方向估算，naive 一次成功率约 60%，远超 25%。要靠加大 r 压下来得 r ≳ 6 cm，那就不是"偏了一点"了。也试过"货架式紧挨排列"：黄油和布丁贴在奶酪两侧，只留 2.6 cm 指缝。实测 MuJoCo 用的是 Panda 手指网格的凸包，外侧从指尖 5.4 cm 斜到上部 6.5 cm（离夹爪中心），偏差为 0 时手指也会楔进指缝，把邻居推开 1–2 cm，成败取决于推不推得动，不干净，所以放弃。最终用 5.0 cm 行程：实测 |b⊥| ≤ 0.5 cm 稳定成功、≥ 1.2 cm 稳定失败。
3. **r 从任务说明的 [2.0, 3.5] cm 调到 [2.5, 4.0] cm**（仍在设计文档的 2–4 cm 内）。这是推算，没有单独实测：容差约 0.7 cm 时，按均匀方向估算 naive 一次成功率约 P(|b⊥| < 0.7) ≈ 2·asin(0.7/r)/π，r ∈ [2, 3.5] 平均约 0.18，r ∈ [2.5, 4] 约 0.14。n = 20 时前者有约 20% 的概率超过 25%，所以留了余量。
4. **真实质量。** LIBERO 默认奶酪 6 g，手指落在边上就把它推走（开发扫描里推移约 0.9 cm），抓取阈值会变宽、变模糊。碗原本 5.6 g，227 g 的奶酪落进去可能把它砸翻（推测，没有单独测）。
5. **抓取高度 = 桌面 + 1.05 cm。** 原来设成 0.8 cm 时手指凸包蹭到桌面，减去真实 b 之后的 oracle 合拢点也在 −x 方向系统性滞后，最大 0.85 cm（实测，8 个 seed）。改成 1.05 cm 后残差 ≤ 0.26 cm。
6. **橙汁盒离奶酪和碗 ≥ 17 cm，离"起始位→奶酪""起始位→碗""奶酪→碗"三条直线路径 ≥ 10 cm；脚本策略先升到桌面 + 20 cm 再移到奶酪上方。** Panda 手掌沿闭合方向宽 ±10.5 cm，抓取和松开时手掌底面比 13 cm 的纸盒顶低。实测：第一次 n = 20 运行里，seed 1003 的 oracle 因手掌碰倒橙汁而失败（当时只要求 ≥ 13 cm）；第二次运行里，seed 1008 在从起始位斜着下降的路上手指碰到纸盒，测得的 grasp_offset 偏了 3.2 cm。两处都修了以后整组重跑，上表是第三次运行的结果。
7. **奶酪 yaw 只在 ±10°。** 这样即使 agent 不转腕，5 cm 开口也夹得住（推算：手指垫宽 1.6 cm，10° 时截面约 4.65 cm < 5 cm），避免混进"抓取朝向"类（L3/L4）失败。
8. **直呼指令不说 "black"。** LIBERO 叫它 akita *black* bowl，但在我们的 OSMesa 渲染里看起来是银灰色、带金色碗沿。场景里只有一个碗，所以直呼版只说 "the bowl"，间接版说 "round grey bowl"。

## within 版本怎么做（未实现）
同一个 episode 不重置：抓空后夹爪抬起，agent 看图像/F2，修正后在原地再抓（奶酪可能已被手指推动 0.5–1.6 cm，要重新感知）；夹住后正常放进碗里。"一次尝试" = 一次合拢（`TrackedSkills.events` 里的 close 事件）。F2 文本与 cross 相同，每次合拢后给出。实现时覆写 `run_scripted`：每次合拢后调一次 `outcome` 的抓取部分，不 reset，adaptive 用同一个 `grasp_offset` 累加。b 在 episode 内不变，难度应和 cross 接近；区别是奶酪会被推动，参照点必须用当前位置。

## 已知问题 / 效度威胁
实测：
- `grasp_offset` 与真实 b 的差（首次尝试）见上表下方统计；所以 F2 下 adaptive 一次失败后几乎必成，F2 版本测的主要是 agent 能不能把"夹爪偏了 X"正确转成"所有指令位置减 X"：符号、坐标系，以及放的时候也要减。
- 失败模式几乎全是 missed_grasp；放置步骤在 naive 下基本不会失败。b∥ 大时偶尔出现 dropped（开发运行见过 1 次；验证运行里 blind 的一次重试也出现过）。
- 夹爪行程是改出来的：渲染出的仍是 Panda 手指，只是张不满。腕部相机里能看到开口只比奶酪宽一点。
- `envs.canonical_quat` 在协调者 10-06 修复之前会把扫描类物体（碗、ramekin）立起来放倒；本任务一开始就不依赖它，用的是 env.reset() 后 LIBERO 自己给的朝向（`self._base_quat`），不受影响。

推测 / 未验证：
- **F0/F1 下信息只在图像里。** 腕部相机在合拢时刻清楚显示手指压在奶酪上；正面 agentview 里夹爪挡住奶酪，偏移不明显。GPT 能否从 512 px 图像估到 < 0.5 cm 未知；harness 需要把合拢时刻的腕部关键帧放进历史。
- **不失败也能测出 b。** harness 有 `pixel_to_world` / 深度工具。agent 可以先把夹爪移到某处，用相机测夹爪真实位置，与自己以为的位置比较，在第一次失败前就标定出 b。这是合理的主动策略，但违背"信息只在失败里"。要么在本任务禁用对夹爪本身的像素测量，要么把它作为单独行为统计。
- **本体感知泄露。** robosuite 观测里的 `robot0_eef_pos` 和 `Skills.eef_pos()` 都是真实位置，直接给 agent 会泄露 b。harness 的 `proprio()` 已经用 true − bias（`agent/tools.py` 第 233 行）；本任务的 `TrackedSkills.move_to` 报告也改成了指令系。其他新接口都要注意。
- blind 的成功率依赖抖动 σ = 5 mm 的选择；σ 更大时 blind 会偶尔撞对。
- 容差 0.5–0.9 cm 之间成败混杂（接触推移带来的物理噪声），所以 naive 的一次成功率对 b⊥ 恰在阈值附近的实例不稳定。
